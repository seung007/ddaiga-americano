# 토큰 규약 — 적게 쓰고 크게 남긴다

**이 파일은 매 세션 통째로 주입된다.** 그래서 여기 적힌 것은 자동으로 적용된다 —
사람이 매번 "토큰 아껴"라고 말할 필요가 없어야 한다. 아래는 **실제로 낭비한 것**에서만 뽑았다.

1. **출력은 받기 전에 줄여라.** 받고 나서 줄이는 건 이미 늦었다.
   2026-09-06에 `search_plugins` 결과가 **90,886자**로 와서 파일로 떨어졌고, 다시 파싱해야 했다.
   같은 날 `web_fetch`가 한강공원 페이지를 **57,680자**로 가져와 통째로 실패했다.
   → 도구는 `--plan`·`grep -c`·`head`·`jq`·`--css-selector`로 **좁혀서 부른다.**

2. **검사는 `npm run check` 하나로.** 개별 검사기를 여섯 번 돌리지 마라.
   통과한 검사기의 출력은 읽을 이유가 없다.

3. **파일은 범위로 읽어라.** `grep -n`으로 줄번호를 먼저 잡고 그 근처만 읽는다.
   통째로 읽는 것은 200줄 미만일 때만.

4. **브라우저는 `get_page_text`·`read_page`가 기본.** 스크린샷은
   **보이는 것 자체가 판정 대상일 때만** 쓴다(레이아웃이 깨졌는가, 사진이 그 신발인가).
   글자를 읽으려고 스크린샷을 찍지 마라.

5. **같은 사실을 두 문서에 적지 마라.** 한 곳에 적고 나머지는 가리킨다.
   지금 `AGENTS.md`·`docs/운영/설정_안내.md`·`docs/운영/스킬_안내.md`가 757줄이고 겹치는 대목이 있다.
   새 문서를 만들기 전에 **기존 문서에 절을 더할 수 있는지 먼저 본다.**

6. **보고는 결론부터 한 줄.** 과정은 사용자가 이미 봤다. 도구 호출 사이에 중계하지 마라.

7. **모델을 루프에서 빼는 것이 최고의 절약이다.** 스크립트가 판정하고 모델은 exit code만 본다.
   검사기 7개·커밋 훅·주간 CI가 그 형태다 — 전부 토큰 0으로 돈다.

> ⚠️ **이 파일 자체가 고정비다.** 매 세션 통째로 들어간다.
> 사례를 더 적을 때는 **규칙이 늘었는지 사례만 늘었는지** 보고, 사례만 늘었으면
> 별도 파일로 뺄 때가 된 것이다.

## 왕복을 줄여라 — 토큰의 대부분은 생각이 아니라 왕복에서 나간다

2026-09-08 에 이 세션을 되짚어 세어 본 결과다. 낭비는 "생각을 길게 해서"가
아니라 **같은 사실을 확인하려고 사람과 여러 번 주고받아서** 생겼다.

| 병목 | 실제로 쓴 비용 | 처방 |
|---|---|---|
| CRLF 경고 106줄이 붙여넣기마다 반복 | 5회 × 2~3천 토큰 | `.gitattributes` 두 줄 |
| 내가 화면을 못 본다 | 오진 1건 + 정정 커밋 1건 + 왕복 6회 | `npm run shot` |
| `&&` 체인이 빈 커밋에서 끊겨 푸시 누락 | 왕복 2회 (옛 코드를 보고 진단했다) | `npm run ship` |
| 같은 Overpass 질의 반복 | 실행 5회 중 3회가 이미 받은 것 | `.cache/osm/` |
| 실패 메시지가 진단을 안 담음 | 406·TypeError·`?? 0` 각각 왕복 1회 | 아래 규칙 |

### 규칙

1. **사람에게 시킬 명령은 한 개로 줄이고, 출력이 짧게 나오게 만들어라.**
   명령 네 개를 주면 출력 네 덩이가 대화로 들어온다. `npm run ship` 하나면
   성공은 두 줄이다. **붙여넣기 비용이 정보량에 비례해야 한다.**
2. **성공은 한 줄, 실패는 전부.** 통과한 검사를 자세히 찍을 이유가 없다.
3. **추측하지 말고 확인해서 알려라.** `ship` 은 마지막에 로컬·원격 해시를
   비교해 "일치"를 찍는다. "푸시됐다"를 믿고 다음으로 넘어가면, 옛 코드를
   보고 내리는 진단이 뒤따른다 — 이 세션에서 실제로 그랬다.
4. **내가 못 하는 일은 사람이 한 번에 하도록 도구를 만들어 줘라.**
   나는 렌더링을 못 본다(샌드박스 네트워크가 npm 말고 전부 403,
   브라우저 바이너리 다운로드도 막힘). 그래서 화면 판정을 말로 주고받는 대신
   `npm run shot` 이 PNG 를 폴더에 떨어뜨리고 **내가 그 이미지를 직접 읽는다.**
   [내 추측 → 사용자 캡처 → 내 정정] 3턴이 [shot → 판단] 1턴이 된다.
5. **같은 것을 두 번 받지 마라.** 외부 조회 결과는 디스크에 캐시한다.
   공개 API 예절 문제이기도 하다.
6. **실패 메시지에 원인을 담아라.** `e.name` 만 찍지 말고 `message` 와
   `cause.code` 를 찍는다. 상태코드는 사람이 할 일별로 갈라 안내한다
   (서버 혼잡 / 코드 문제). 이 세션에서 부실한 실패 메시지가 왕복 세 번을 만들었다.

### 지금 있는 한 방 명령

```bash
npm run ship "메시지"   # 검사 -> 커밋 -> 푸시 -> 원격 일치 확인. 성공은 두 줄
npm run shot            # 배포 화면을 shots/ 에 PNG 로. Claude 가 직접 읽는다
npm run shot:local      # localhost:3000 을 찍는다 (npm run dev 를 먼저 켠다)
                        # `npm run shot -- --local` 은 인수가 안 넘어간 적이 있다.
                        # 전용 스크립트를 쓰면 그 실패 방식이 사라진다.
npm run routes          # 코스 경로선 (캐시됨, --fresh 로 무시)
```

⚠️ **샌드박스에서 `npm i` 를 돌릴 때는 `--ignore-scripts` 를 붙여라.**
`playwright` 가 devDependency 라서 설치 후 브라우저 바이너리를 내려받는데,
샌드박스는 그 다운로드가 막혀 있어 `npm i` 전체가 실패한다.
브라우저는 사람 PC 에만 있으면 된다.

## 스킬 라우팅 — 고민하지 말고 표를 보고 골라라

스킬이 25개를 넘었다(2026-09-06, SearchFit SEO 17개 설치). **어느 것을 쓸지 매번
따져보는 것 자체가 토큰이다.** 상황 → 스킬을 한 번에 정한다. 표에 없으면 스킬 없이 한다.

| 상황 | 쓸 것 |
|---|---|
| 논문·스펙·거리처럼 **틀리면 신뢰가 무너지는 것**을 쓸 때 | `grounded` |
| 웹에서 데이터를 긁어야 할 때 · `web_fetch` 실패 · 봇 차단 | `scrapling-official` |
| 큰 파일·긴 출력·과설계 위험 | `lean` |
| 구글 색인·크롤·속도 문제 | `searchfit-seo:technical-seo` |
| 새 페이지가 색인될 길이 있는지 | `searchfit-seo:internal-linking` |
| 어느 검색어를 노릴지 | `searchfit-seo:keyword-clustering` |
| 특정 페이지 제목·메타 최적화 | `searchfit-seo:on-page-seo` |
| 구조화 데이터(JSON-LD) | `searchfit-seo:schema-markup` |
| 되돌리기 비싼 결정 | `council` **(토큰 많이 — 아껴 쓴다)** |
| 우선순위가 헷갈릴 때 | `ai-saas-builder` |

**구매 링크·사진·인용·영상 검사는 스킬이 아니라 `npm run check`다.** 저장소 검사기가
더 정밀하고 토큰이 0이다. `searchfit-seo:broken-links`와 겹치면 **우리 것을 쓴다.**

### 대량 탐색은 서브에이전트로 넘겨라 — 이게 가장 큰 절약이다

`seo-auditor`·`content-strategist`·`competitor-analyzer`는 **별도 문맥에서 돈다.**
사이트를 크롤하고 파일을 훑는 과정이 이쪽 대화에 안 쌓이고 **결론만 돌아온다.**

그러므로 **"여러 파일·여러 페이지를 훑어야 답이 나오는 일"은 직접 하지 말고 넘긴다.**
직접 하면 훑은 내용이 전부 문맥에 남지만, 넘기면 요약 한 덩어리로 끝난다.
반대로 **파일 한두 개를 고치는 일은 넘기지 마라** — 넘기는 비용이 더 크다.
