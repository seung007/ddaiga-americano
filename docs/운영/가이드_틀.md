# 새 글·페이지 규칙 — 답을 바로 찾게 쓴다 (2026-11-02)

사람들이 검색창 대신 생성형 AI 에 묻는다. AI 는 **질문-답이 바로 붙은 짧은 문단**과 **날짜·작성 주체가 보이는 글**을 인용하기 쉽다
(hyun 님이 공유한 카드뉴스의 다섯 원칙. 효과는 우리가 측정하지 않았다 — 그래서 「신뢰」 규칙과 겹치는 부분만 강제한다).
러닝 가이드·블로그 원고·새 콘텐츠 페이지를 만들거나 고칠 때:

1. **소제목은 질문형으로** — 사람들이 실제로 묻는 말(「정강이가 아픈데 계속 뛰어도 되나요?」). 답은 그 아래 첫 문장에
2. **한 문단에 한 내용** — 앞뒤를 안 읽어도 그 문단만으로 이해되게
3. **어려운 말은 뜻부터** — 드롭·스택·케이던스·2E 같은 말이 처음 나오면 「○○는 ~입니다」 한 문장
4. **긴 설명은 표·FAQ 로** — 가이드는 `FaqSection` 3문항 이상. 표는 근거 있는 열만(「표는 문장보다 위험하다」)
5. **누가·언제** — 가이드는 제목 아래 `<ArticleMeta href=…>`, 날짜는 원장 `lib/guide/articles.ts` 의 `updated` 에만 적는다.
   **글을 고치면 updated 도 같이 고친다.** 저자는 사이트 이름까지만 — 전문 자격을 지어내지 않는다

기계로 셀 수 있는 것(①·④·⑤의 빠뜨림, 새 틀 글은 ③도)은 `npm run check:geo` 가 막는다. 대회·러닝화 상세의 FAQ 는 데이터에서 자동으로 만든다(`lib/faq.ts`) —
값이 없으면 그 질문을 만들지 않는다.

## 가이드 글 틀 — 2026-11-18 확정, 바꾸지 않는다 (견본: `app/injury/start-running/page.tsx`)

근거: `docs/조사/벤치마킹_2026-09-12.md` 「가이드 글 부분 구성」 1·2(국내 한국어 글 실측). 부품은 `components/guide/Read.tsx` 아래쪽.
순서: 제목(질문형) → `<ArticleMeta compact>` 날짜 한 줄 → `<KeyPoints>` 3줄 요약 → `<Lead>`(숫자·예고 문장 없이) → 번호 목차 →
번호 붙은 큰 질문 4~6개(`<Num>`): 첫 문장이 답 → 2문장 안팎 문단 → 할 일은 `<Steps>`(①②③) → 절 끝 `<OneLine>` →
FAQ 3문항+ → `<Sources>` → `<AuthorNote>`. 날짜 줄은 「최종 수정 날짜 · 연구 N편 대조」(`checked={N}`, check:geo 가 출처 개수와 대조).
`<Sources>` 는 접힌 채 작은 글씨 한 줄(근거와 출처 · 연구 N편과 하나씩 대조했어요 · 펼치기), 펼치면 항목마다
1줄 `<strong>저자 (연도)</strong> 확인한 결과` / 2줄 `<Ref>학술지 권(호):쪽 · 링크</Ref>`(사용자 선택 ①안, 2026-11-18).
- **딱지·접힘을 쓰지 않는다**: 「저희 제안」「연구 근거」 딱지, 「근거 보기」 접힘, 문장 끝 [n], 따옴표, ※, 문장 속 → 없음
- **「N분 읽기」를 쓰지 않는다**(2026-11-18) — 잰 값이 아니었다. 사이트 전체에서 뺐다
- **요약 문장(`<KeyPoints>`·`<OneLine>`)은 사람 말로** (2026-11-18, 견본 3줄 요약을 고치며 정함 — 27편 바꿀 때 이 기준으로 고친다)
  - 본문을 읽어야 아는 말을 쓰지 않는다. 요약은 진도표보다 먼저 읽힌다: 「다음 날 아프면 그 단계를 한 번 더」 ✗ → 「다음 날 아프면 더 늘리지 말고, 같은 양으로 다시 뛰어요」
  - 기준을 명사로 압축하지 않는다: 「속도는 말하면서 뛸 수 있을 만큼이에요」 ✗ → 「옆 사람과 이야기할 수 있을 만큼 천천히 뛰어요」
  - 논문 표현을 옮기지 않는다: 「걸음이 바뀔 만큼 아프면」 ✗ → 「걸을 때도 아프면」. 쉬운 말로 바꿀 때 근거보다 넓히지 않는다 — 「걸을 때 아프면」은 살짝 뻐근한 것까지 걸려 넓다, 「때도」 한 글자로 맞춘다
  - 세 줄을 같은 리듬(「A는 B. C하면 D」)으로 쓰지 않는다 — 표를 읽는 느낌이 난다
  - 사이트가 정한 기준의 말끝은 「권해요」(「추천해요」 대신, 다른 글과 맞춤)
- **어려운 말은 처음 나올 때 풀이를 붙인다 — 모양은 셋만** (2026-11-18, `check:geo` 가 본다): 괄호 「체질량지수(BMI)」 /
  「피로골절은 ~금이에요」 / 「이걸 말하기 테스트라고 해요」. 영문 약어는 목록 없이 잡고, 한글 전문어는 `scripts/check-geo.mjs` 의 TERMS 에 있는 것만 잡는다 —
  글을 바꾸다 새 전문어가 나오면 TERMS 에 더한다. FAQ 는 답 하나만 따로 인용되므로 문항마다 다시 풀이한다
- **할 일이 먼저, 이유는 뒤** (2026-11-18): 「왜 그런가」만 설명하는 절을 따로 두지 않는다 — 이유는 할 일 절 안에 한두 문장으로. 읽는 시간의 대부분이 첫 두 화면에 쓰인다(NN/g 2018).
  글이 길면 **페이지를 나누지 않고 덜어낸다** — 본문과 FAQ 에 같은 내용이면 한 곳만, 곁가지 소제목은 FAQ 로(견본 8.7 → 7.5화면)
- **작은 제목(h3)은 결론형, 큰 제목만 질문형** (2026-11-18): 「가장 길게 뛰는 날은 한 달 최장 기록의 110%까지」. 다른 글로 보내는 링크는 상황 문장으로(「정강이가 아프다면 →」)
- **견본에서 이미 판정·정정한 주장은 다시 틀리지 않는다** — 목록은 견본 `page.tsx` 머리 주석 「고친 것」(환기역치 아래 ✗ · Relph OR 7.56 ✗ · 「체력이 아니라」 ✗ ·
  「비싼 신발」 → 발 모양 맞춤 신발 · Linton 86% 는 출판본 기준 확인). 같은 주장이 다른 글에 나오면 같은 판정을 쓴다. 판정 전체 보고서는 Project 문서 「처음 달리기 글 근거 판정」
- **`running-guide-writing` 스킬은 이 틀보다 먼저 만든 것이다** — 어긋나면(「~합니다」 예시, 3줄 요약 없음) 이 절이 이긴다. 스킬에서는 제목 짓기·오픈채팅 사람 수 세기만 가져다 쓴다
- **한국에서 쓰는 말과 단위로** (2026-11-19, hyun 님 지적 「네 주 안쪽」「2마일」): 기간은 숫자로(「6주」「3개월」 — 「한 번·한 달·두 배」 같은 일상어는 그대로),
  「~ 안쪽」 대신 「4주만 쉬어도」「4주 안에」. 마일·파운드·인치는 km·kg·cm 로 환산해 「약 3.2km」로 쓰고(환산은 계산이다) 원래 단위는 접힌 출처에만 괄호로.
  FAQ 답은 **130자·4문장 안**(견본 62~110자) — 길면 곁가지 연구를 빼고 본문에 맡긴다. 전부 `check:geo` 가 본다
- **FAQ 답도 본문과 같은 규칙** (2026-11-18): 첫 문장이 답 → 할 일 → 이유·연구는 끝에 한 번. 할 일과 핵심 숫자 1~3곳을 `**…**` 로 굵게
  (`FaqSection` 이 화면에선 굵게, 구조화 데이터에선 표시를 지운다). `check:geo` 가 굵은 곳 수·연구 언급 수를 본다. 규칙 전에 바꾼 글은 FAQ_TODO 에서 하나씩 뺀다
- **본문의 주어는 연구가 아니라 독자가 할 일이다**(2026-11-18, 국내 러닝 글 3편 실측: 연구 언급 0~2문장). 연구 언급은 절마다 많아야 한 번,
  짧게. 연구 대상·인원·나라는 접힌 출처에만 둔다
- **근거의 무게는 말의 세기가 진다** — 주장마다 논문으로 판정해서: 확실(체계적 고찰·여러 연구 일치) → 단정 /
  근거 있음(연구 한두 편) → 한 단계 약하게(「~경향이 있었어요」「~많아요」「~편이 좋아요」) / 근거 없음(사이트가 정한 진도·기준) → 「권해요·해 보세요」.
