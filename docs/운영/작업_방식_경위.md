# 작업 방식 — **Cowork 단독** (2026-09-16~)

2026-09-15~16 에 Claude Code(코드)와 Cowork(콘텐츠·설계)로 나눠 작업했다가 **하루 만에 되돌렸다.**

**왜 되돌렸나 — hyun 님 판단**
- 설계 문서 → Claude Code → 회신 → 다시 Cowork 로 **같은 내용이 두 대화에 두 번씩 쌓여 토큰이 두 배**로 들었다
- 판단 근거는 Cowork 에, 실행 결과는 Claude Code 에 있어서 **사람이 한 곳에서 흐름을 이어 볼 수 없었다**
- 같은 사실을 양쪽이 각자 다시 확인했다(대회 마감일 · 공식 URL)

**지금 규칙**
1. **Cowork 가 코드·콘텐츠·문서를 전부 고친다.** 담당 구역 없음
2. **Cowork 는 PC 셸로 폴더의 파일을 직접 고치고 `npm run check` 도 직접 돌린다** (2026-10-14 확인 — 9/16 의 Windows 문제가 풀렸다).
   **`.patch` 로 넘기지 않는다.** 넘기면 적용·정리가 사람 몫이 되고, 그게 반영된 패치 27개가 쌓인 이유다.
   PC 연결이 끊겼을 때만 `Claude outputs/` 에 패치로 넘긴다 — 반영된 패치는 `ship` 이 `_archive/patches/` 로 옮긴다.
   **`npm run ship`(커밋·푸시·배포)은 hyun 님이 돌린다.** PC 셸은 삭제 권한이 없으면 git 이 lock 파일을 못 지워
   커밋이 깨진다(도구 안내). 푸시 자격 증명이 있는지는 확인하지 않았다
3. **Claude Code 는 hyun 님이 요청할 때만** 쓴다. 그때도 긴 설계 문서를 넘기지 않고 **할 일 몇 줄**만 준다
4. 설계 문서(`docs/설계/`)를 새로 만들지 않는다. 결정은 **해당 코드 주석이나 기존 문서에 한 줄**로 남긴다

**치운 것** — `check:zones` 를 `npm run check` 에서 뺐다. 혼자 작업하면 코드와 콘텐츠를 같이 고치는 게 정상인데
그 검사가 매번 커밋을 막는다. `scripts/check-zones.mjs` 와 `npm run check:zones` 는 남겨 뒀다 — 다시 나눌 때 쓴다.
